## 還沒解決、等負責人決定的

第二次冷讀時，冷讀者站在「應該一起設計」的立場讀，畫面與結論只有部分一致。

- 回程箭頭直接連到每個 core，和「只在一個窄介面相接」矛盾。
- 最強的反駁有兩個：
  - 兩邊共用 page table。PTE 的格式兩邊都得懂，圖上沒有畫 page table。
  - 壓縮層要用 CPU MMU 那邊的機制清每個 core 的 TLB。

提議的第三版是：
- 畫出 page table，標明它屬於 CPU MMU 那邊。
- 中間改成一個要一起講定的小介面，列三項：request、PTE 格式、清每個 core 的 TLB 這項服務。所有往來都經過它。
- 結論改成「兩邊只在一份小的、事先講定的介面相接，其他分開設計與開發」。

這一版還沒畫，等負責人決定。
