# 驗收紀錄：two-stage-task 第 3 張第四版，gen11

日期 2026-11-15。OpenAI `gpt-image-2.5-sunburst`，high，1536x1024。

負責人指出第三版會被讀成「壓縮層 kernel SW 是一份獨立執行的 instance，所有 core 把 request 送過去」。第三版有幾處會造成這種讀法：
- 方塊寫「kernel SW: one manager」與「takes every request」。
- 箭頭從 processor 出發，標「page fault from any core」。
- 表格第一列寫壓縮這邊的工作「in one manager, for all cores」。

這和 `sim/hostsim/kernel.py` 的 `page_fault` 不符。實際的設計是：壓縮層的程式在 fault 的那個 core、那個 thread 上接著跑，好幾個 core 可以同時在跑；`mm_lock` 只讓共用的步驟一次一個。只有一份的是共用的東西：COT、chunk pool、LZ4 HW、將來的 HW assist。

第四版的改法，提示詞在 `prompts.md`，第三版的提示詞存在 `prompts-v8.md`：

| 位置 | 第三版 | 第四版 |
|---|---|---|
| 方塊 | kernel SW: one manager，takes every request | 三張疊起來的卡片，kernel SW: one module，runs on the core that faulted, many at once |
| 方塊下的小字 | runs on a core like any kernel SW...，may dispatch to parallel workers... | owns the COT and the chunk pool，a lock keeps only the shared steps one at a time |
| 左邊箭頭 | page fault from any core | page fault: a call on the same core |
| 右邊箭頭 | one entry point | one entry function |
| 表格第一列 | where the work runs | what is shared |
| 表格第三列 | how it scales：one copy per core | how hardware scales：one TLB per core |
| 便條 | 兩邊長在不同地方 | both run on the core that faulted，but their state and hardware help live in different places |
| Key point | 無 | 加一句：Its code runs on every core at once; locks keep only the shared steps one at a time. |
| ONE PER CORE | 在 page table 正下方 | 移到 page table 右邊 |

## 冷讀

報告在 `blind-review/cold-read-gen11-20261115.md`。冷讀者站在「應該一起設計」的立場讀，另外被問到壓縮層 kernel SW 在執行上是什麼樣子。

| 項目 | 結果 |
|---|---|
| 困惑指數 | 2 |
| 角色是否清楚 | 是 |
| 畫面與結論是否一致 | 一致 |
| 執行方式的讀法 | 在 fault 的 core 上以 function call 進入；好幾份同時跑；兩個 core 同時 fault 時各跑各的，碰到 COT 與 chunk pool 時由 lock 一次過一個 |
| 決定 | 採用 |

冷讀者自己的結論：壓縮層和 TLB miss handler 一樣在 fault 的 core 上跑，可以好幾個 core 同時跑；但它管的 COT、chunk pool 與將來的硬體幫手是所有 core 共用一份，CPU MMU 的硬體幫手 TLB 是每個 core 一份。兩邊長大的方向不同，所以只一起約定一個小 interface，其餘分開設計。

## 記錄不改的小瑕疵

| 項目 | 說明 |
|---|---|
| 位置與文字 | 疊卡畫在離 processor 很遠的另一個框裡，沒有接到 core。「在 fault 的 core 上跑」完全靠文字撐起來 |
| 疊卡 | 緊貼 PROPOSAL，也可能讀成好幾個提案版本或排隊的 job |
| Key point | 寫 every core，比畫面上的 the core that faulted 說得強 |
| once | a sub-action, once verified in SW 的 once 有兩種讀法 |
| more engines | 表格提到，圖上沒有對應的東西 |
| COT | 沒有寫全名 |

## 冷讀者沒被擋住的反駁

這些是內容的問題，重生解決不了。

| 反駁 | 說明 |
|---|---|
| 介面不小 | 清每個 core 的 TLB 與 page table 的 lock 規則都是大題目 |
| 兩把 lock | 巢狀順序、會不會 deadlock、各握多久，正好需要兩邊一起設計 |
| TLB miss 是 hot path | refill 要不要拿 lock，PTE 裡壓縮過的標記怎麼編，會影響 CPU MMU 那一邊 |
| reclaim 路徑沒畫 | 誰挑要壓的 page、accessed 由誰記、趕出時怎麼讓 PTE 失效並清每個 core 的 TLB |
| 時序 | CPU MMU 還沒 bring up，PTE 格式可能在壓縮層的需求進來前就定案 |
| 共用 L2 | 兩邊的表在 L2 裡競爭 |
