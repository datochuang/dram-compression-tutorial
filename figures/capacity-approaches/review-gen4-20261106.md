## 冷讀結果

困惑指數 2，角色清楚，畫面與結論一致，有回答「怎麼省到空間」，沒有誤以為壓縮比固定。冷讀者讀到的數字是舉例，但可能把 2.1KB 到 3.8KB 當成大致範圍，也不知道系統層級能多出多少容量。冷讀者的結論：

> Page 壓小之後空出 DRAM，空出來的地方再放別的 page，OS 就看到比實際安裝更多的記憶體。A 是硬體壓所有 page，B 是硬體只壓 cold page，C 是 OS 把 cold page 放進獨立的 compressed tier，並以 NUMA node 的額外容量呈現。B 和 C 省空間的原理看起來相同，差在誰來挑、OS 看到什麼。

記錄不改的小瑕疵：
- `4KB page` 白條比右邊整條（綠色加虛線）長約一成，prompt 要求等長。
- 做法 A 的 After 有兩個綠格接近一格寬，這是刻意的（對應壓縮效果差的 page），但可能被看成沒有變小。
- "Who picks" 的綠底與壓縮 page 同色；灰底不在這張的圖例裡。
- "HRT range not shown" 在這張沒有定義 HRT。
- 檔名 `01-` 對應徽章 "2"。
