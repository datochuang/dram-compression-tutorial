|---|---|---|---|

## 2. 看不懂的線或物件

1. **是依 client 還是依地址分流？** 兩條輸入線和兩條輸出線的顏色一一對應（深藍接深藍、綠接綠），看起來是依 client 分流；但方塊寫的是「地址範圍判斷」，輸出標的也是「範圍」。圖沒有回答 CPU 存取 HRT 範圍、或 Display 存取壓縮區時會怎樣。
2. **「直通」卻穿過壓縮層**：線畫成穿過綠色方塊，副標又說不壓縮。讀者會想問 HRT 流量是否仍有經過這一層的延遲。
3. **做法 C 接不上共同路徑**：做法 C 從 VA 開始，A、B 從 OSPA 開始，但上半部的地址判斷沒標示用哪一種地址。VA 到 PTE 應該發生在進壓縮層之前，圖上看不出 C 怎麼套進「同一個壓縮層」這個框架。
4. **「不查 metadata」的用詞範圍**：metadata 只出現在做法 A，B 用 CTE、C 用 PTE。不確定這句話對 B、C 是否指同一件事。
5. **「寫入先搬回 DRAM」**：主題是 DRAM compression，壓縮區照理也在 DRAM 裡。這裡的 DRAM 應該是指未壓縮的 DRAM，但字面上像是壓縮 NUMA node 不在 DRAM。
6. **「資料變大」列的語意不一**：A 講的是壓縮後變大如何容納；B 講的是存取冷 page 時解壓搬移，沒回答熱區資料變大怎麼辦；C 是用唯讀來避開問題。同一列標籤下回答的不是同一個問題。
7. **格子看不出省了容量**：綠色格子填滿整條，沒有空出來的部分，「省容量」這個主旨沒有被畫出來。
8. **「硬體透明」加上 balloon driver**：做法 A 名稱寫透明，同時又要加 driver。內容有明寫，不算錯，但第一眼會停一下。

顏色相關的困惑見第 7 節。

## 3. 圖說的一句話

（不看 Key takeaway）所有 client 共用一個壓縮層，依地址範圍讓 HRT 範圍直通不壓縮、其他範圍進壓縮區；壓縮區可以用硬體透明超賣、硬體冷熱分層、OS 管理 tier 三種做法管理，它們在地址對應、資料變大、實體用完、OS 改動與代價上各有不同。

## 4. 畫面與 Key takeaway 是否一致

Key takeaway 原文：「HRT 走固定對應；三種做法的差別在壓縮區由誰管，以及實體用完時誰負責」

**判定：部分一致。**

| Takeaway 的主張 | 畫面是否支持 | 說明 |
|---|---|---|
| HRT 走固定對應 | 支持 | 上半部的不壓縮區與直通線講得很清楚 |
| 差別在壓縮區由誰管 | 大致支持 | 欄位標題（硬體、硬體、OS）與 OS 改動列（少、少、多）都有呈現，但 A 和 B 同為硬體，這一條分不開它們 |
| 差別在實體用完時誰負責 | **不支持** | 「實體用完」列三欄全是灰色，依圖例就是三種都由 OS 處理。顏色傳達的是「沒有差別」，和結論相反 |

其他不一致：

- **顏色的差異落在另一列**：實際變色的是「資料變大」列（綠、綠、灰）。照顏色讀，結論應該是「資料變大時誰處理」，不是「實體用完時誰負責」。
- **副標和 takeaway 說法不同**：副標說差別在「怎麼對應、怎麼回收」，takeaway 說「由誰管、實體用完誰負責」。對應鏈在 takeaway 裡消失了，「由誰管」則沒出現在副標裡。
- **畫面內容比結論多**：主要代價是相當顯眼的一列，takeaway 完全沒提。

## 7. 顏色的意義是否一致

**不一致。** 圖例只定義兩色：綠色是硬體處理、灰色是 OS 處理。實際使用的狀況如下：

| 問題 | 位置 | 說明 |
|---|---|---|
| 綠色身兼多義 | 其他 clients 的線、壓縮區、對應鏈箭頭、Key takeaway 標籤、標題編號與底線 | 有的是「壓縮路徑」，有的只是裝飾，都不是「硬體處理」 |
| 和做法 C 矛盾 | 壓縮區與 C 的對應鏈箭頭 | 壓縮區是綠色（硬體處理），卻由包含 OS 管理的三種做法管理；C 的 VA → PTE 箭頭也是綠色 |
| 深藍色不在圖例 | HRT 線、方框外框與標題文字 | HRT 線的深藍顯然有意義，但沒有定義 |
| 白色不在圖例 | OS 改動列、主要代價列、對應鏈方塊 | 列內容可以理解成「不分誰處理」，但 metadata、CTE、PTE 由誰處理就看不出來了 |
| 混合情況被壓成單色 | 做法 B 的實體用完 | 「壓更多冷 page」看起來是硬體動作，「不夠再請 OS 回收」才是 OS，整格卻都是灰色 |

## 8. 用自己的話說結論

SoC 上所有流量都經過同一個壓縮層，HRT 用的地址範圍保持固定對應、不壓縮，以確保即時性；其他範圍進壓縮區，而壓縮區有三種管法。A 和 B 由硬體管理，OS 幾乎不用改，但要付出多查 metadata 或搬移解壓延遲的代價；C 交給 OS 管理，硬體比較單純，但 OS 要改很多，寫入多時效益也會下降。實體記憶體不夠時，三者最後都要靠 OS 參與。

最後一句正是我和 takeaway 讀法不同的地方：我從畫面讀到的是「三者最後都靠 OS」，takeaway 說的卻是「誰負責」是差別所在。

## 10. 是否建議重生

**建議重生。** 觸發條件是畫面與結論不完全一致：takeaway 說實體用完時誰負責是差別所在，但該列三欄同色，依圖例就是三種都由 OS 處理。

這不是整張圖的問題，版面結構不需要動，建議只修以下幾點：

1. **讓「實體用完」列和 takeaway 對得上**：拆開做法 B 那格的硬體與 OS 動作，呈現各做法的實際分工；如果三者確實都靠 OS，就改寫 takeaway，不要把它當成差別。
2. **整理顏色語意**：讓綠色只代表硬體處理，壓縮路徑與裝飾改用其他顏色；把深藍和白色補進圖例，或讓它們不帶語意。
3. **統一副標和 takeaway 的比較軸**。
4. **補上 OSPA、CTE 的全名或一句說明**，並替對應鏈那一排加上列標籤。
5. **交代做法 C 和共同路徑的關係**，說明 VA → PTE 發生在壓縮層之前或之外。
