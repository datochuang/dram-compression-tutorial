SoC DRAM compression · 3D lessons

一次只看一個 page：誰讀、誰寫、寫了什麼

每一課只講一個場景，貼近到每個 byte。USER SW 是被服務的程式，KERNEL SW 與 LZ4 HW 是兩個角色，job descriptor、COT entry 與 completion 都攤開成一格一個 byte 的板子，逐步看是誰寫的、誰讀過。

給第一次接觸這個主題的人。所有數字都來自 simulator 的同一次執行（seed 1），不是編的例子。按 Next 一步一步看，舞台可以拖曳旋轉。

先看全貌 · Address space view

這一頁沒有角色，兩種設計共用。看的是 symbol 在哪裡、三張表怎麼跟著變，不是誰寫了哪個 byte。

3D兩種設計共用

一個 symbol，在兩個 address space 裡的樣子

程式看到的 symbol 是一段連續的 logical address。到了 DRAM，它被切成 page，有的在 hot region 的 frame 裡，有的壓縮後散在 cold region 的 chunk 裡。六個場景逐步看一次 access 讓 PTE、kernel page state、COT entry 哪一格被改寫，資料在 frame、LZ4 HW 與 chunk 之間怎麼流。也可以點 symbol 自己發 access。

偏硬體的設計 · HW-leaning

COT 與 free-chunk stack 都由 LZ4 HW 自己管。kernel 只說「哪個 page、放哪裡」。

HW-LEANING第 1 課

COMPRESS：把一個 RW page 壓進 chunk

UI 要一個 frame，kernel 挑中 LOG 的 page 0x4F5，把 PTE 改成 invalid，交代 LZ4 HW 壓縮。4096 B 變成 1938 B，放進 4 個 chunk，COT entry 一組一組欄位寫出來。

HW-LEANING第 2 課

DECOMPRESS：PTE invalid 觸發的解壓縮

LOG 又來讀 page 0x4F5，被 access gate 擋下。kernel 拿一個空 frame，交代兩個 job：DECOMPRESS 把資料解回 frame，INVALIDATE 把 4 個 chunk 還回 stack、COT entry 清成 0。最後才把 PTE 寫回 valid。

偏軟體的設計 · SW-leaning

chunk 號碼改由 kernel 自己記，直接寫在 descriptor 裡；硬體每個 job 不留狀態。

SW-LEANING第 3 課

COMPRESS：kernel 先訂好 chunk，再交代硬體

和第 1 課是同一次 access、同一個 page 0x4F5。kernel 先在自己的 bitmap 找 7 個空 chunk，把號碼寫進 48 B 的 descriptor。LZ4 HW 照著寫，只用了 4 個。kernel 讀 completion 後自己寫 COT entry，再把沒用到的 3 個 chunk 還回 bitmap。

SW-LEANING第 4 課

DECOMPRESS：一個 job，收尾由 kernel 自己做
