PTE 是 CPU MMU 唯一會讀的東西。Kernel 的 page 狀態只有 kernel 自己看。COT entry 告訴 LZ4 HW 壓縮後的 stream 在哪幾個 chunk。這一步有變動的格子會標色。

Logical page這個 page 上的 symbolPTEKernel page stateCOT entry：chunk 依 stream 順序壓縮後大小

圖只畫出可壓縮區段裡的一小段：3 個 RO page、5 個 RW page、7 個 frame 和 48 個 chunk。一個 frame 的面積等於 8 個 chunk。

PTE 只畫 valid bit 和 frame 號碼。Invalid 的 PTE 對 CPU MMU 來說沒有其他內容，page 是在 cold region 還是根本沒配置，要看 kernel 自己的 page 狀態。

壓縮後的大小是用 simulator 裡同一套 LZ4 對範例內容逐頁壓縮得到的。

COT 由誰讀寫、空 chunk 由誰管理，HW-leaning 和 SW-leaning 兩種設計不同，這一頁不區分，標成 KERNEL / LZ4 HW。逐 byte 的過程見 3D 課程。

這一頁等到 frame 用完才回收。實際的 kernel 在空 frame 低於門檻時就開始回收。
